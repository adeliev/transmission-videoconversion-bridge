# Transmission Video Conversion Bridge

Автоматизированный конвейер загрузки, конвертации и тегирования фильмов и сериалов на базе Transmission и Docker.

**Русская версия** | **[English](README.md)**

## Описание

Этот проект — Docker-контейнер с Transmission, расширенный цепочкой скриптов, которая превращает скачанный торрент в полностью готовый к просмотру файл: с правильным именем, метаданными и на своём месте в библиотеке:

- Автоматический подхват завершённых загрузок (фильмы и сериалы, отдельные серии или целые сезоны разом)
- Конвертация видео в MP4/H.264 с фильтрацией аудио- и субтитровых дорожек до нужных языков
- Имена файлов и папок берутся из реального названия релиза на трекере (формат rutracker), а не из часто нечитаемого исходного имени файла
- Полное тегирование через TMDB API — теги в стиле iTunes (название, актёры/съёмочная группа, описание, постер, возрастной рейтинг) как для фильмов, так и для серий
- Автоматическая раскладка по нужным папкам библиотеки, включая определение кириллицы/латиницы в названии сериала
- Мониторинг watch-папки для автоматического добавления `.torrent`-файлов

## Возможности

- **Полностью автоматический конвейер**: цикл каждые 30 минут прогоняет convert → rename → tag → publish без единого ручного шага
- **Фильмы и сериалы**: определение сезона/серии по названию релиза на трекере, включая русский формат многосезонных паков (`Сериал-N (NN сер.)`) и паки вообще без маркеров серии в именах файлов
- **Умное переименование**: имя и структура папок берутся из разобранного названия торрента (title, сезон, год, страна), а не из сырого имени файла в раздаче
- **Фильтрация аудио/субтитров**: остаются только нужные языки (по умолчанию русский/английский/словацкий/чешский), полные субтитры предпочитаются форсированным
- **TMDB-интеграция**: приоритет русских метаданных с автоматическим фолбэком на поиск по оригинальному названию/без года, если строгий запрос ничего не находит
- **Тегирование на уровне Subler**: возрастной рейтинг и полный состав актёров/съёмочной группы/студии (`iTunEXTC`/`iTunMOVI`), побайтово совпадает с тем, что даёт Subler
- **Безопасная конкурентность**: файловые блокировки на каждом этапе — ручной запуск никогда не столкнётся с плановым циклом
- **Один bind mount на закачки, стейджинг и библиотеку**: избегает медленного copy+delete внутри контейнера — всё на одном маунте, поэтому `mv` — это мгновенное переименование

## Структура проекта

```
transmission-videoconversion-bridge/
├── Dockerfile                    # Образ Docker с зависимостями (ffmpeg, python3, mutagen, ...)
├── docker-compose.yml            # Конфигурация Docker Compose
├── docker-compose.example.yml    # Шаблон для копирования и адаптации
├── scripts/
│   ├── move.sh                   # torrent-done хук: переносит готовые файлы в стейджинг
│   ├── watch_new_torrents.sh     # фоновый поллер, сохраняет "богатое" имя торрента до того,
│   │                              # как Transmission перезапишет его реальными метаданными файла
│   ├── convert.sh                # конвертация видео в MP4/H.264 через ffmpeg
│   ├── get_ffmpeg_map.py         # решает, какие аудио/субтитровые дорожки оставить, по языку
│   ├── rename.sh                 # раскладывает файлы по Сериал/Сезон или в чистое имя фильма
│   ├── parse_torrent_name.py     # разбирает имя релиза в формате rutracker на поля
│   ├── plan_tv_episode_names.py  # угадывает номера серий для паков без sXXeYY-маркеров
│   ├── tv_info.py                # определение сезона/серии, включая русские форматы паков
│   ├── read_torrent_info.py      # читает поля обратно из сайдкара .torrentinfo.json
│   ├── is_cyrillic.py            # проверка кириллица/латиница, определяет папку/раскладку
│   ├── clean_name.py             # фолбэк-очистка имени, если разбора имени торрента нет
│   ├── tag.sh / tmdb_tagger.py    # запрос к TMDB + полное тегирование метаданными/постером/актёрами
│   ├── publish.sh                # переносит полностью оттегированные файлы из стейджинга в библиотеку
│   └── monitor.sh                # планировщик: convert → rename → tag → publish, каждые 30 минут
├── init-scripts/                 # скрипты автозапуска контейнера
├── config/                       # конфигурация Transmission (не в git)
├── logs/                         # логи по каждому этапу (не в git)
└── watch/                        # папка мониторинга торрентов (не в git)
```

## Установка

### Предварительные требования

- Docker
- Docker Compose
- Папка медиатеки на хосте (используется и под закачки, и под библиотеку — см. примечание ниже)

### Быстрый старт

1. Клонируйте репозиторий:
```bash
git clone https://github.com/adeliev/transmission-videoconversion-bridge.git
cd transmission-videoconversion-bridge
```

2. Скопируйте пример конфигурации:
```bash
cp docker-compose.example.yml docker-compose.yml
```

3. Отредактируйте `docker-compose.yml`:
   - Измените `USER` и `PASS` для веб-интерфейса
   - Укажите `/path/to/your/media` — реальный путь на хосте (см. **Монтируемые тома** ниже — этот один маунт одновременно служит и папкой закачек, и стейджингом обработки, и финальной библиотекой)
   - Укажите правильный часовой пояс
   - Если хотите, чтобы входящие пир-соединения нормально работали — прокиньте пир-порт (`51414` по умолчанию) на роутере на этот хост, TCP+UDP, с одинаковым номером порта по обе стороны маппинга в `ports:`

4. Создайте необходимые папки:
```bash
mkdir -p config watch logs init-scripts
```

5. Запустите контейнер:
```bash
docker compose up -d
```

6. Откройте веб-интерфейс Transmission:
```
http://localhost:9091
```

## Конфигурация

### Переменные окружения

- `PUID` / `PGID` - ID пользователя и группы для правильных прав доступа
- `TZ` - Часовой пояс
- `USER` / `PASS` - Учётные данные для веб-интерфейса
- `TRANSMISSION_SCRIPT_TORRENT_DONE_ENABLED` - Включение скрипта пост-обработки
- `TRANSMISSION_SCRIPT_TORRENT_DONE_FILENAME` - Путь к скрипту обработки

### Монтируемые тома

- `./config` - Конфигурация Transmission
- `./scripts` - Скрипты обработки
- `./logs` - Файлы логов
- `./watch` - Папка автоматического добавления торрентов
- `/path/to/your/media:/media` - **единый маунт**, покрывающий:
  - Папки закачки самого Transmission (`<media>/Downloads/incomplete`, `.../complete`)
  - Стейджинг обработки (`<media>/Downloads/Movies/...`, `<media>/Downloads/TV-Shows/...`)
  - Финальную библиотеку (`<media>/New`, `<media>/Series`, `<media>/TVShows`)

  Все они должны быть на **одном и том же** bind mount. Если хоть один из них — отдельный маунт, любой `mv` между этапами превращается внутри контейнера в copy+delete, даже если сами пути на хосте физически лежат на одном диске — bind mount'ы Docker это отдельные точки монтирования независимо от файловой системы хоста под ними.

### Порты

- `9091` - Веб-интерфейс Transmission
- `51414` - Пир-порт BitTorrent (TCP/UDP)

Порт хоста и внутренний `peer-port` контейнера (в `config/settings.json`) **обязаны совпадать** — BitTorrent анонсирует трекерам/DHT/пирам именно свой внутренний порт прослушивания, и если проброс хост→контейнер делает ремап на другой номер порта, входящие соединения тихо никогда не долетают, даже если проброс на роутере в остальном настроен верно. Проверить доступность порта в любой момент:
```bash
docker exec transmission-downloader transmission-remote -n <user>:<pass> -pt
```

## Как это работает

Весь конвейер управляется `monitor.sh`, который каждые 30 минут прогоняет `convert.sh → rename.sh → tag.sh → publish.sh` (плюс независимый фоновый поллер `watch_new_torrents.sh`).

1. **Загрузка**: Transmission качает в `<media>/Downloads/incomplete`, затем в `.../complete`.
2. **Захват имени релиза**: сразу при добавлении торрента `watch_new_torrents.sh` сохраняет его полное "богатое" имя в формате rutracker (название, диапазон сезон/серии, год, страна, жанр) из магнет-ссылки — это нужно сделать немедленно, потому что Transmission перезапишет отображаемое имя торрента реальными метаданными файла, как только их получит.
3. **Перенос**: по завершении `move.sh` (хук `torrent-done`) разбирает сохранённое имя через `parse_torrent_name.py`, решает фильм это или сериал **один раз на весь торрент** (а не на каждый файл отдельно), и переносит видеофайл(ы) в стейджинг, прикладывая сайдкар `.torrentinfo.json` с разобранными полями.
4. **Конвертация**: `convert.sh` перекодирует в MP4/H.264 при необходимости, используя `get_ffmpeg_map.py`, чтобы оставить только нужные языки аудио/субтитров.
5. **Переименование**: `rename.sh` раскладывает файлы стейджинга по разобранному имени торрента — `Сериал/Сезон N/Сериал - sNNeNN.mp4` для сериалов (или `Season N`, если название сериала латиницей), чистое `Название (Год).mp4` для фильмов. Для паков без узнаваемых маркеров серии в именах файлов `plan_tv_episode_names.py` вычисляет номер серии по тому единственному токену в имени, который реально меняется в пределах пака.
6. **Тегирование**: `tag.sh`/`tmdb_tagger.py` ищет название на TMDB (с приоритетом русского языка, с фолбэком на неограниченный поиск, если строгий запрос ничего не нашёл), вклеивает полные теги в стиле iTunes плюс постер и актёров/съёмочную группу, и только после этого удаляет сайдкар `.torrentinfo.json` — если тегирование не удалось, сайдкар остаётся, чтобы можно было опознать файл как всё ещё недоделанный.
7. **Публикация**: `publish.sh` переносит полностью оттегированные фильмы прямиком в `<media>/New`, а сезоны сериалов — в `<media>/Series` (кириллические названия) или `<media>/TVShows` (латиница), публикуя сезон только когда абсолютно все файлы, лежащие под него в стейджинге, полностью оттегированы.

## Диагностика проблем

- **Файл как будто завис / никогда не публикуется**: посмотрите `logs/tag.log` по этому файлу. `tag.sh` помечает каждый обработанный файл как "попытка совершена" в момент запуска, даже если поиск в TMDB не удался (чтобы не долбить API вечно по реально ненайденному названию) — а значит и *временный* сбой (кратковременный DNS/сетевой глюк, или просто неверное название в торренте) тоже может залипнуть навсегда как "уже пробовали". Починка: убедитесь, что реальная причина сбоя устранена, удалите точный путь этого файла из `config/tagged_files.txt`, затем вручную перезапустите `tag.sh` и `publish.sh`.
- **Нестабильная, низкая скорость закачки при видимых пирах/сидах**: проверьте `transmission-remote -pt` (тест порта). Если он показывает закрытый порт — входящие соединения от пиров вообще до вас не долетают, вы ограничены только теми пирами, кто способен сам к вам достучаться, а это малая часть любого роя. См. раздел **Порты** выше про обязательное совпадение портов хост/контейнер и проброс на роутере.
